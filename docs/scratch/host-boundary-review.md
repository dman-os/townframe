# Plugin host boundary review: the author's path

Status: Draft
Owner: nodules lane
Updated: 2026-11-18
Scope: What a plugin author (human, agent, or eventually an end user) meets writing a nodule (`big_ndk`) or a micro (`clay_mdk`) in a cartridge, read from the code in worktree `net-wash`. All paths are relative to `src/` unless they start with `docs/`. Read-only; nothing was built or run, so "builds" claims are from comments and manifests, not from running them.

Caveat (manager, 2026-11-18): this reads the nodules stack at node-56. claytxt's `feat/cartridge-micros` (`f2d03a27`, not in this tree) adds `uses` to micro contributions (`MicroContribution.uses`, `lower_uses`, `ResolvedGrants::from_grants`), so re-check the micro edges (4 and the isomorphism table) against that branch before acting on them. Question 4 below (nodule queries) is an implementation gap, not a product question: dispatch already serves queries to nodules, so `export_nodule!` should too.

## Summary

The two runtimes do not yet feel isomorphic; today they are two different products with one shared word, "cartridge". A nodule author writes a Rust handler with `big_ndk::export_nodule!` and a hand-built `Cartridge` struct (no builder exists), and talks JSON/XRPC with raw capability ids visible on `Cx`. A micro author writes a `MicroManifest` (a separate, older vocabulary of publications, requirements, collection requests, configuration requests), publishes CBOR calls and Dioxus views, and has no permbinds, `uses`, `#net`, blobs, `MissingAuthority`, or runtime grant request at all in the MDK. Neither side has a "new plugin" template, one build command, or a path from source to an installed cartridge that is not test fixtures. Lexicons for nodule methods are hand-written JSON in every example found. The sharpest edges for end-user programmability are: no manifest builder, no schema derivation for author-declared methods, capability plumbing exposed as strings, and the micro side not speaking ADR 049 yet.

## The author's path

### Nodule

1. **Start.** No template or generator found. The exemplar is a two-crate pair: handlers in a plain crate (`test_nodule_handlers/lib.rs`) and a 5-line `cdylib` guest (`test_nodule_guest/lib.rs:5`, `Cargo.toml:15-17`) that lives in the separate `src/wasm_utils_rs` workspace (`test_nodule_guest/Cargo.toml:8`, `wasm_utils_rs/Cargo.toml:24-32`) with a `guardrails.toml` build contract (`test_nodule_guest/guardrails.toml:7`). The only build command found is in a test doc comment: `cargo build --manifest-path src/wasm_utils_rs/Cargo.toml -p test_nodule_guest --target wasm32-wasip3 --release` (`big_node/e2e/nodule_wasm.rs:5`). WIT is vendored inside `big_ndk` (`big_ndk/wit/world.wit`, `big_ndk/wit/deps/*`), so the author needs no WIT deps of their own. Concepts before hello world: `methods!`, `Handler<M>`, `Cx`, `export_nodule!`, two crates, two workspaces, wasip3, a cartridge manifest, lexicons, permbinds, `uses`.
2. **Declare methods.** `method_core::methods! { error = E, nsid_prefix = "..."; Req => Out, procedure, "name"; }` (`big_ndk/lib.rs:8-11`). Procedures only; queries and subscriptions are compile errors (`big_ndk/lib.rs:41-42`). Then implement `big_ndk::Handler<M>` (`big_ndk/lib.rs:80-82`) and export with `export_nodule!(Type => [A, B])` (`big_ndk/lib.rs:92-137`); `Type: Default`, fresh per request (`big_ndk/lib.rs:88-89`).
3. **Declare the cartridge.** Build a `Cartridge` by struct literal: `Cartridge::new(id, version)` then assign `authority`, `nodule`, `permbinds`, and call `.with_lexicon(file)` / `.with_wasm(key, bytes)` (these are in `big_cartridges_core::test_support::FixtureCartridge`, `big_cartridges_core/lib.rs:566-679`). Each routine is a `Routine { r#impl: RoutineImpl::ComponentExport(ComponentExport { component, export, extra }), implements, uses, extra }` (`big_ndk_testing/smoke.rs:109-118`). Each permbind is a `Permbind::Method(PermbindMethod { nsid, description, necessity, min_revision, extra })` (`big_ndk_testing/smoke.rs:175-182`). Lexicons are `serde_json::json!` documents written by hand (`big_ndk_testing/smoke.rs:100-137`). No builder exists, though ADR 049 §2 says there will be one (`docs/adrs/049-*.md:90-92`); grep for `CartridgeBuilder|NoduleBuilder` finds nothing.
4. **Call things.** `cx.call(Typed)` for methods (`big_ndk/cx.rs:376-390`), `cx.read_config` / `cx.write_config` for settings (`big_ndk/cx.rs:201-253`), `cx.fetch` for `#net` (`big_ndk/cx.rs:333-371`). Drawers and blobs have no typed helpers: `cx.drawer_capability()` and `cx.blobs_capability()` return a bare string (`big_ndk/cx.rs:191-197`) that the author must splice into a request by hand (`test_nodule_handlers/lib.rs:253-290`).
5. **Test.** `big_ndk_testing::node().with_nodule(cartridge, MyNodule::default()).boot().await` boots a real in-memory node with a native executor, then `enable`, `grant`, `call`, `invoke` (`big_ndk_testing/lib.rs:1-30, 74-289`). The wasm bytes are placeholders; the native executor never loads the component (`big_ndk_testing/smoke.rs:150-154`). Wasm-specific behavior is covered by a separate e2e that requires a pre-built guest (`big_node/e2e/nodule_wasm.rs:5`).
6. **Install and iterate on a real node.** The CLI `day carts` has one subcommand found, `dev-takeover` (`day_cli/cmds/carts.rs:9-27`); install/publish are protocol methods (`InstallCartridge`, `StageCartridgeVersion`, `big_cartridges_core/lib.rs:604`, `big_ndk_testing/lib.rs:36-38`) with no author-facing CLI found. Takeover needs `dev.allow_slot_takeover` in `node.json` (`day_cli/cmds/carts.rs:14-17`; `docs/adrs/045-*.md:49`). Hot reload: not found.

### Micro

1. **Start.** Two crates by convention: `micro_<name>` (cdylib + rlib) and `micro_<name>_manifest` (`micro_counter/Cargo.toml`, `micro_counter_manifest/Cargo.toml`; `clay_mdk/README.md:46-51`). `micro_counter/Cargo.toml` has target-conditional `clay_mdk` features (`guest` on wasi, `in_process`+`view` otherwise) and a git-rev Dioxus fork dependency (line 12). Build is via `x/check-dayframe.ts` / `x/dayframe-packages.ts:25-38` with `--target wasm32-wasip3`; README step 4 says to name the crate `micro_<name>` so a script discovers it (`clay_mdk/README.md:53-71`), and the WIT fetch instruction names `src/api_utils_rs`, which does not exist in the tree (`clay_mdk/README.md:74`; `ls src` shows only `wasm_utils_rs`).
2. **Declare.** Rust struct literal `MicroManifest { entrypoints, publications, requires, configuration_requests, collection_contracts, collection_requests, contributions, extra }` (`micro_counter_manifest/lib.rs:53-146`), repeated constants for names (`micro_counter_manifest/lib.rs:28-51`), emitted as a sibling `<name>.manifest.json` that "is not embedded in the Wasm" (`clay_mdk/README.md:38-41`). Cartridge side: `MicroContribution { component, schema, description: IndexMap<String, Value> }` carries it as an opaque JSON object (`big_cartridges_core/lib.rs:347-355`).
3. **Call things.** `activate(Context)` publishes components and calls (`micro_counter/lib.rs:63-111`). Reads and writes go through facets of a configuration document (`context.config(NAME).facet::<T>(tag, key)`, `micro_counter/lib.rs:65-67`; `clay_mdk/context.rs:409`) or collections (`clay_mdk/context.rs:718`); other micros through `context.require(binding)` and `Capability::call` with CBOR (`clay_mdk/context.rs:165-182, 705`).
4. **Test.** The native `ACTIVATE` entry is linked in-process in a unit test of ~60 lines of host plumbing (`micro_counter/lib.rs:193-269`); the guest build is "exercised by the engine tests over the wasm component" (`micro_counter/lib.rs:191-192`).
5. **Install.** README: append an entry to the shell's `guest_providers` in `dayframe_desktop/composition.rs` and `dayframe_web/main.rs`, plus configuration maps in `dayframe_composition::CompositionRuntime::new` (`clay_mdk/README.md:55-71`). This is recompiling the shell, not installing a cartridge; "Package delivery belongs to `big_cartridges`, which will replace this pairing" (`clay_mdk/README.md:41-42`).

## Isomorphism gaps

| Task | Nodule (`big_ndk`) | Micro (`clay_mdk`) | Gap |
|------|--------------------|--------------------|-----|
| Entry point | `export_nodule!(Type => [Methods])` (`big_ndk/lib.rs:92`) | `export_micro!(activate, manifest_fn)` (`clay_mdk/lib.rs:331`) | Name, arity, and what is declared where differ: nodule takes methods and a handler type, micro takes a closure and a manifest function |
| Declare what it uses | `Routine.uses` over cartridge `permbinds` (`docs/adrs/047-*.md:§3`) | `requires`, `configuration_requests`, `collection_requests` on `MicroManifest` (`micro_counter_manifest/lib.rs:78-116`) | Different vocabulary; `MicroContribution` carries it as opaque JSON (`big_cartridges_core/lib.rs:347-355`) |
| Serve a method | `Handler<M>::call(&self, &Cx, M) -> Result<Out, Err>`, JSON, XRPC (`big_ndk/lib.rs:80-82`) | `context.publish_call(NAME, \|req: Req\| async { Result<Resp, Error> })`, CBOR (`micro_counter/lib.rs:79-109`; `clay_mdk/context.rs:165-182`) | Wire (JSON vs CBOR), error type (method-defined vs `clay_mdk::Error`), contract (Lexicon NSID vs `Nsid::literal` plus string publication name) |
| Call another provider's method | `cx.call(TypedMethod)` through `dispatch.local` (`big_ndk/cx.rs:376`) | `context.require(binding)?.call(&req)` via a binding name, untyped by NSID (`clay_mdk/context.rs:705, 165`) | Typed by method vs by binding string; micro has no `dispatch.local` call at all |
| Read/write settings | `cx.read_config(Option<BTreeSet<String>>)` returns `Value` (`big_ndk/cx.rs:201`) | `context.config(name)?.facet::<T>(tag, key)` with `current()`, `write()`, `refresh()` (`clay_mdk/context.rs:409, 475-503`) | Micro gets a typed watched facet with pending/settle receipts; nodule gets untyped JSON |
| Datums in drawers | raw `drawer_capability()` string (`big_ndk/cx.rs:191`) | collections and `use_rows` (`clay_mdk/context.rs:718`) | No shared type |
| Network | `cx.fetch(..)` under `#net` (`big_ndk/cx.rs:333`) | not found in `clay_mdk` (`grep fetch` in `clay_mdk/*.rs` finds only a mirror test); `docs/adrs/049-*.md:131-136` says UI sinks need `#net` | Missing on micro |
| Blobs | `blobs_capability()` plus hand-built request (`test_nodule_handlers/lib.rs:253`) | not found | Missing on both as typed API |
| Missing grant | `ContextError::MissingAuthority { cartridge, permbind, request }` (`method_core/lib.rs:44`; `big_ndk/lib.rs:33-39`) | `Error::Denied` / `Rejected(String)` only (`clay_mdk/context.rs:37-58`); `ctx.request` is design only (`docs/adrs/049-*.md:224-238`) | Micro cannot tell "ungranted" from "forbidden" and cannot ask |

| Test harness | `big_ndk_testing::node()` real in-memory node, native executor (`big_ndk_testing/lib.rs:74-289`) | hand-wired `Host`, `Supervisor`, `Resources`, `CapabilitySession` (`micro_counter/lib.rs:193-269`) | Harness shape differs; micro has no `enable`/`grant`/`call` equivalent |
| Package/install | registry stage then `InstallCartridge` pin (`big_ndk_testing/lib.rs:36-38`) | sibling `.component.wasm` + `.manifest.json`, composition-root edit (`clay_mdk/README.md:38-42, 55-71`) | Not the same artifact; micro is not yet installable as a cartridge contribution |

## End-user programmability blockers

1. **Rust-only, and two workspaces, wasip3.** `export_nodule!` and `export_micro!` are Rust macros (`big_ndk/lib.rs:92`, `clay_mdk/lib.rs:331`). The host contract is plain `wasi:http` (`big_ndk/lib.rs:1-4, 26-31`), so another language could target it in principle, but the header contract, `dispatch.local` egress and capability headers are documented only in rustdoc and a test fixture (`test_nodule_handlers/lib.rs:1-60`). No language-neutral spec found.
2. **No declarative manifest source.** There is no JSON/TOML cartridge format an author or agent can write by hand and have validated; the artifact is a serialized `Cartridge`, authored via Rust literals (`big_ndk_testing/smoke.rs:91-200`). ADR 047 `§2` shows the JSON shape, but no tool turns it into a staged cartridge.
3. **Lexicons by hand.** A non-Rust author must write atproto Lexicon JSON and the handler separately, with nothing checking they agree (see edge 2).
4. **The `#hosted` component kind is proposal only.** ADR 047 amendment B (a language runtime cartridge plus pinned or drawer-referenced sources, grants bound to the host manifest) is "not accepted" (`docs/adrs/047-*.md`, "Amendments proposed 2026-11-17"); it is the intended path for scripting and agent-written plugins and nothing in code implements it (grep for `hosted` not performed beyond ADR; mark as not found in code).
5. **Dioxus + Rust for micros.** The only micro view API is a Dioxus fork pinned by git rev (`micro_counter/Cargo.toml:12`) rendering over a mutation wire (`clay_mdk/README.md:120-140`). A TS tier is mentioned (`docs/adrs/049-*.md:131`, "the TS tier") but no code found.
6. **Trap semantics.** A panic in a guest kills the instance and every outstanding call (`clay_mdk/README.md:101-104`). An agent-written or user-written micro cannot be given that blast radius without isolation per call.
7. **Capability concepts leak.** An author must understand "caller capability" vs "nodule capability" vs "config capability" and why a nested call must not pass idempotency (`big_ndk/cx.rs:166-177, 380-386`).
8. **Feedback loop.** Placeholder-wasm native testing is fast but not the production path (`big_ndk_testing/smoke.rs:150-154`); the wasm path needs a pre-built guest (`big_node/e2e/nodule_wasm.rs:5`); a micro "iteration" is a shell recompile (`clay_mdk/README.md:55-71`). No dev server or watch/hot-reload found for either runtime.

## Questions for the operator

1. Is the authoring surface for non-Rust authors a JSON/TOML cartridge file plus Lexicon files (and the host validates), a Rust-only builder, or both? ADR 049 §2 says "a builder"; end-user programmability suggests a declarative format must exist underneath.
2. Should the micro adopt cartridge `permbinds`/`uses` now, replacing `requires` / `configuration_requests` / `collection_requests`, or do those stay as a separate micro-internal vocabulary beside `uses`?
3. Should nodule methods be authored from Rust types (Lexicon derived) or Lexicon-first (types generated)? This decides edge 2 and blocks any non-Rust path.
4. Is a nodule allowed to serve queries (GET), given dispatch already serves them to nodules? Today the macro refuses them.
5. Which of `#hosted` (047 amendment B) or a second guest language is the first end-user programming surface, so the SDK shape can be chosen to fit it?
