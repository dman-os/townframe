## Pending decisions

1. **Authenticated physical retirement and fresh-node bootstrap.** Stable register joins and semantic settlement do not authorize deleting historical writer fences or all BigSync membership/cursor metadata. Keep current required evidence until a bounded authenticated retirement/reintroduction contract is agreed. Continue task execution, encrypted publication, domain settlement and live networking independently; do not claim bounded lifetime storage.
2. **Unwitnessed candidate promotion defaults.** ADR 010 leaves promotion timing/eligibility open. Implement durable observations and ordinary coordination reconciliation without inventing an adoption election or automatically replaying historical documents on enablement. Record concrete blocked behavior before selecting a new product policy.
3. **Historical authorization across revocation.** Existing issue #53 tracks backdated native proof admission. Preserve the policy-neutral reducer and checked current host delivery/action permissions; do not treat frontier signatures as Byzantine completeness or historical membership proof.
4. **Image routine selection for non-main Blob facets.** The real import/image run also scheduled embed-image and ocr-image on an OCI manifest document whose Blob key was content-addressed, not main. Both routines failed at their explicit blob/main lookup (`plug_test/wflows/embed_image.rs:32`, `ocr_image.rs:30`). The manifest predicate accepts any Blob tag, while routine input selects the main key. Evidence: `/tmp/distributed-goal-real-image-label-narrow.log` lines 116–123. Do not hide those failures with Not(PlugManifest) or empty success; decide whether image routines are main-key-only or need facet-level input selection, then align the declared predicate and invocation contract.
5. **Processor predicates and execution meaning — baseline decided.** Offer snapshot and delta predicate styles according to processor design. Delta-dependent execution compares against the last successfully incorporated settlement, not the last admitted/evaluated heads. Enqueueing, cancellation, and failure do not advance processed heads. Capture the exact baseline and target in each invocation and bind the baseline into deterministic task identity when it affects input. Overlapping deltas during an in-flight attempt are accepted. An older success winning finalization settles only its own generation; existing invocations retain their capture. This decision does not add debouncing, queue coalescing, or distribution-mode migration.
6. **Unified slot state and retained processed heads — agreed direction.** Use the same processor-slot bookkeeping, settlement writes and walker sparse projection for local-only and distributed processing. Retain exact incorporated source heads with processor/config generations in settlement; this enriches evidence without reopening existing settlement semantics or preferring incremental execution. Local-only processor parts remain node-local: no remote subscription, advertisement or serving. Distributed parts synchronize only through explicit composition and native authority. Per-node processing retains independent node-local baselines despite identical logical slot identities. Replace the separate local ProcessorRunLog path in the unified cutover, preserving durable incorporation-before-settlement and accepted concurrent evidence/retention rules. DeltaWalkerSparseStateRepo is the local transactional projection, not the replicated slot store itself. Remaining work is implementing and proving these contracts, not selecting new settlement policy merely because heads were added.

release persists Active before captured workload startup/JobInit, but workload
startup errors escape before attempt failure settlement. Startup loads retained
workloads without repairing Active rows lacking JobInit. The recovery owner must
settle startup failure and reconcile retained job identity against actual durable
JobInit without duplicating queued jobs, covering both sides of the append/deets
crash cut. This is a current runtime correctness issue, not a substitute for the
missing distributed TaskRepo. The document store and independently opened
same-scope SqlitePartStore have different revision Notifies; more importantly,
native document scope is document-only. Dedicated task storage shares one Notify
across its actual owner/readers/worker/RPC, leaving document and local derived
boundaries intact. The transport owner covers a reader opened before publication.
